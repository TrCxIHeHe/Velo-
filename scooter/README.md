# Velo — Scooter Platform

Dock-based electric scooter sharing platform.
Track A Phase 1: Authentication Service + Flutter Login/Onboarding/Profile.

---

## Architecture overview

```
Velo-/
├── backend/          FastAPI + PostgreSQL (Docker)
└── scooter/          Flutter app (Android-first, iOS-compatible)
```

**Backend:** FastAPI modular monolith, PostgreSQL, SQLAlchemy async, Alembic migrations, JWT + Firebase Phone Auth, refresh token rotation with reuse detection.

**Frontend:** Flutter 3.44.4, Riverpod state management, GoRouter navigation, Dio HTTP client with silent token refresh, FlutterSecureStorage.

**Auth flow:**
```
User enters phone
  → Firebase OTP
  → Firebase ID Token
  → POST /api/v1/auth/login
  → Backend verifies Firebase token (phone extracted server-side)
  → Returns access_token + refresh_token + user
  → Tokens stored in FlutterSecureStorage
  → If user.name == null → Onboarding
  → Else → Profile
```

## Setup

### Step 1 — Backend

```bash
cd backend
cp .env.example .env
```

Edit `.env`:
- `JWT_SECRET` → run `openssl rand -hex 32` and paste the output
- `FIREBASE_PROJECT_ID` → your Firebase project ID (e.g. `velo-cd57c`)
- `FIREBASE_SERVICE_ACCOUNT_PATH` → `./firebase-service-account.json`

Download Firebase service account key:
Firebase Console → Project Settings → Service Accounts → Generate new private key
Save as `backend/firebase-service-account.json`

Start backend:
```bash
docker compose up --build -d
docker compose exec api alembic upgrade head
```

Verify:
```bash
curl http://localhost:8000/api/v1/health
# Expected: {"success":true,"data":{"status":"ok"}}
```

---

### Step 2 — Firebase Console configuration

#### 2a. Enable Phone Authentication
Firebase Console → Authentication → Sign-in method → Phone → Enable

#### 2b. Add test phone numbers (mandatory for emulator development)
Firebase Console → Authentication → Sign-in method → Phone → Scroll to
"Phone numbers for testing" → Add phone number

Recommended test numbers:
```
+91 98765 00001  →  OTP: 123456
+91 98765 00002  →  OTP: 123456
```

These bypass real SMS entirely. Use them on both emulator and physical device
during development. Real SMS works automatically on physical devices with real
numbers — test numbers are just an addition, not a replacement.

#### 2c. SHA-1 fingerprint for Android (required for Firebase Phone Auth on physical device)
```bash
cd android
./gradlew signingReport
```
Copy the SHA-1 from the `debug` variant.
Firebase Console → Project Settings → Your apps → Android app → Add fingerprint.

Not required for emulator.

## Running the app

### Android emulator

```bash
# From scooter/ directory
flutter run -d Medium_Phone --dart-define=API_BASE_URL=http://10.0.2.2:8000/api/v1
```

`10.0.2.2` is the Android emulator's alias for the host machine's localhost.
Backend must be running on port 8000.

### Android physical device

Find your machine's LAN IP:
```powershell
ipconfig | Select-String "IPv4"
```

```bash
flutter run -d <device-id> --dart-define=API_BASE_URL=http://192.168.x.x:8000/api/v1
```

Device and machine must be on the same WiFi network.

### iOS simulator (macOS only)

```bash
flutter run -d "iPhone 15" --dart-define=API_BASE_URL=http://127.0.0.1:8000/api/v1
```

## End-to-end flow

```
1. App launches → Splash (checks secure storage for existing tokens)
2. No tokens found → Login screen
3. Enter test phone number: +91 98765 00001
4. Tap Send OTP
5. Firebase sends OTP (or uses test fixed code: 123456)
6. Enter 123456 → Tap Verify
7. Firebase returns ID token
8. App calls POST /api/v1/auth/login with Firebase ID token
9. Backend verifies token, creates user, returns session
10. Tokens stored in FlutterSecureStorage
11. user.name is null (first login) → Onboarding screen
12. Enter name → Tap Continue
13. App calls PATCH /api/v1/auth/me
14. Backend updates name, returns updated user
15. Router redirects → Profile screen
16. Profile shows name, phone, role
17. Tap refresh icon → re-fetches GET /api/v1/auth/me
18. Tap Log out → dialog → POST /api/v1/auth/logout → tokens cleared → Login screen
```

On subsequent logins (token still valid):
```
Splash → checkSession() → GET /api/v1/auth/me succeeds → Profile directly
```

## Token lifecycle

| Token | Lifetime | Storage |
|---|---|---|
| Access token | 15 minutes | FlutterSecureStorage |
| Refresh token | 30 days | FlutterSecureStorage |

**Silent refresh:** The Dio `TokenInterceptor` intercepts any 401 response,
calls `POST /api/v1/auth/refresh` automatically, stores both new tokens, and
retries the original request. The user never sees a login prompt unless the
refresh token itself has expired or been revoked.

**Reuse detection:** If a previously-rotated refresh token is presented, the
backend revokes the entire token family and returns `AUTH_REFRESH_REUSE`.
The app clears storage and redirects to login.

## Environment variables

The only runtime variable is the backend URL, passed at build time:

```bash
--dart-define=API_BASE_URL=http://<host>:8000/api/v1
```

| Target | Value |
|---|---|
| Android emulator | `http://10.0.2.2:8000/api/v1` |
| iOS simulator | `http://127.0.0.1:8000/api/v1` |
| Physical device (same WiFi) | `http://192.168.x.x:8000/api/v1` |
| Production | `https://api.yourcompany.com/api/v1` |

No `.env` file is needed for Flutter. The value is compiled into the binary
via `String.fromEnvironment`.

## Troubleshooting

### App stuck on splash screen
**Cause:** Auth state never transitions from `AuthInitial`.
**Check:** Backend is running. `curl http://localhost:8000/api/v1/health` returns 200.
**Check:** Emulator can reach backend — open Chrome on emulator and navigate to `http://10.0.2.2:8000/api/v1/health`.

### OTP never arrives / Firebase verification fails on emulator
**Cause:** Test phone numbers not configured, or emulator uses Google Play image instead of Google APIs.
**Fix:** Add test numbers in Firebase Console (see Setup Step 2b).
**Fix:** Ensure emulator uses Google APIs image, not Google Play.

### `SocketException: Connection refused`
**Cause:** Wrong `API_BASE_URL` for the target device type.
**Fix:** Use `10.0.2.2` for emulator, LAN IP for physical device.

### `AUTH_INVALID_FIREBASE_TOKEN`
**Cause:** Firebase service account not configured on backend, or wrong `FIREBASE_PROJECT_ID` in `.env`.
**Fix:** Verify `backend/.env` has correct `FIREBASE_PROJECT_ID` and `firebase-service-account.json` exists.

### `cleartext HTTP traffic not permitted` on Android
**Cause:** Missing `android:usesCleartextTraffic="true"` in `AndroidManifest.xml`.
**Fix:** Add to `<application>` tag (development only — use HTTPS in production).

### `pod install` fails on iOS
**Cause:** Minimum deployment target too low.
**Fix:** Ensure `ios/Podfile` first line is `platform :ios, '13.0'`.

### Gradle build fails with version warnings
**Cause:** Flutter version check on Gradle/AGP versions.
**Fix:** Add `--android-skip-build-dependency-validation` flag.
```bash
flutter run -d Medium_Phone \
  --dart-define=API_BASE_URL=http://10.0.2.2:8000/api/v1 \
  --android-skip-build-dependency-validation
```

## Backend API reference (Phase 1)

| Method | Endpoint | Auth | Description |
|---|---|---|---|
| GET | `/api/v1/health` | None | Liveness probe |
| POST | `/api/v1/auth/login` | None | Exchange Firebase ID token for session |
| POST | `/api/v1/auth/refresh` | None | Rotate refresh token |
| POST | `/api/v1/auth/logout` | None | Revoke refresh token |
| GET | `/api/v1/auth/me` | Bearer | Get user profile |
| PATCH | `/api/v1/auth/me` | Bearer | Update display name |

Interactive docs (development only): `http://localhost:8000/docs`
